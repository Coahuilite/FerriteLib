# 0.8.0-rc2 — retained layout and dependable verification

Release candidate for **RimWorld 1.6**, not a stable/latest release. FerriteLib remains a no-content
prerequisite with one runtime DLL, no Defs/patches/textures and no settings or save data of its own.

## Changes from rc1

- Native event mapping uses explicit enum values; Repeat template-root visibility follows the normal
  invalidation path.
- Canonical palette lookup avoids repeated parsing/reflection. Resolved appearance and detached rollback
  facts are reused only while their actual declaration, ancestor, theme and font inputs remain valid.
- The shared synchronous layout pipeline validates stable domains before full candidate preparation.
  It uses first-write leaf records, first-touch arrangement backups and immutable sparse geometry.
  Unknown/legacy/structural domains retain the complete transaction, including multi-root remaining-height
  dependencies. Draw, current hit geometry, native editors and required Repaint calls remain active.
- Verification now restores explicit roots once, builds distinct Core/Release/Dev variants and executes
  the built outputs. Stub dependencies share the normal graph. Complete logs and input/configuration,
  exit and timing summaries survive failures as well as success.

## Compatibility and upgrade

Supported 0.8 source, compiled-consumer, XML and legal-use contracts remain protected. There is no new
purity/subscription prerequisite for ordinary getters, old Measure or ITextMetrics. The API/build base
remains 0.8.0; the rc2 tag/archive identifies the trial, while the DLL additionally records its real source
commit. Retained domains still perform validity/Draw/hit walks; this is not pixel retention or automatic
background layout.

Exit the game before replacing the complete FerriteLib folder with the selected package. Keep exactly
one enabled carrier of FerriteLib.UiKit.dll; do not put a second copy in a consumer mod. Consumers compile
against that exact fixed DLL with Private=false and assert their supported API range, normally
[0.8.0,0.9.0). Keep the last accepted complete consumer/library pair for rollback. Do not clear player
configuration to upgrade the library, and do not disable it while an enabled consumer depends on it.

For publication, consume the actual rc2 asset and its real tag/full source SHA when those exist.
A local producer input is not a published asset or a future main merge commit.

## Acceptance and known scope

The user accepted stable FPS for US2f22bec/FL833c14f4 and subsequently accepted the overall internal
trial of USea610fa/FL833c14f4 as “work fine” for RC preparation. Those observations retain their original
identities. The trial did not supply a granular all-action, resolution, language or IME record.
Automated protocol/stub checks and overall trial acceptance answer different questions.

Cold-opening peaks, independent HUD cost, detailed font/IME/overlap/scaling and real configuration-save
coverage remain incompletely characterized. Previously observed headless game errors remain accepted as
non-blocking for this transition. No compiled/native 1.7 adapter, new window manager or asynchronous
dispatch is delivered; later-platform/window work is not a prerequisite for this 1.6 RC.
