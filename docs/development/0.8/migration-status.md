# Complete first-version migration status

## 2026-10-23 closeout: complete scope and evidence classes

The reactive foundation/RU1 path now feeds RU2 captured measurement and independently retained local
arrangement plans. Explicit and default nested scopes own stage records; parent dimensions, Scroll
content/range and shared-label results propagate to their real consumers. All18 default registered
uses participate, with Repeat on the container path. [Layout reuse](layout-reuse-contract.md) is the
single stage/custom/metric contract; the [reactive contract](reactive-foundation-contract.md) retains
business/graph/presentation ownership. Full automatic data migration is not inferred from a layout
cache: ordinary getters still need their original notifications, old custom Measure is validated at its
original legal sync, and unknown metric services gain no new text-purity requirement.

RU2 evidence is `LayoutReuseTests` (same production neutral validity/results/layout with both business
examples) and `KernelLayoutReuseTests` (actual Host/node counters, geometry, input, Scroll/shared results,
identity and all-kind/all-container participation). The existing purpose-specific lanes below remain
applicable to their unchanged interaction contracts and now exercise the default captured calculations.
RU2 purpose-specific cases include WrapperInputs (tree/image/options/progress and multiline draft),
PopupAndDraft (dropdown anchor and numeric draft), and SharedResults (number/slider label geometry),
alongside the retained full-purpose lanes below. Native acceptance and RU4/RU5 stay separate.

This is the maintained inventory for the complete 0.8 first version, not a list of only the latest
slice. **Exists** means the retained production use is present. **Migrated** names the applicable 0.8
capability already connected. **Automated** distinguishes new shared-contract tests from legacy
regression coverage. **Native** means acceptance of these 0.8 inputs in RimWorld 1.6; all rows remain
pending. Earlier 0.7 human acceptance stays attached to its own package and does not close these rows.

## RU3 non-kind connections and remaining migration levels

All nine containers retain the same transactional geometry path. Known Hidden/VisibleKey/Tab demand is read before visiting an exclusive default subtree; shared layout results remain consumers. Shared width/items failure stops the actual Host geometry/input boundary, not business. Row/Column/Surface and actual Repeat failure fixtures exercise these edges; the full existing LayoutReuse AllUses and container/placement/scroll/clip guards remain applicable to unchanged geometry rules.

Standard and embedded Host share SetDisplayDemand and current fault boundaries. Real standard-shell fixtures distinguish B input focus, explicit hidden demand, A/B shared owner and idempotent close; owned confirmation keeps A17 after B23 selection and business execution rejects current ineligibility. No B-local-modal backend or universal occlusion analysis is claimed. External adapters/services are not paused implicitly.

Bindings/presentation expose per-key current validity and Retry; consumer callbacks expose owner-controlled IsPaused/Fault/Resume. Pure-cycle and per-response propagation-budget diagnostics identify actual computation/response paths. Node.ReactiveFault and Host.LayoutFault are additional located runtime facts, not a second business graph; existing bounded observation/instrument tests remain. XML/program assembly and definition rollback keep their original boundary. Retained snapshots reject changed definition/interaction scope; ordinary getters and ITextMetrics keep their original conditions. Optional IUiPresentationDemand is the complete custom tracked-key entrance; unknown old custom receives conservative all-key service, not inferred savings or required purity.

The production same-source FailureLifetimeTests and actual KernelFailureLifetimeTests compile FailureLifetimeExamples.cs for both counter and independent workshop. They add sustained failure/recovery, resolved labels, default editable/selection controls, shared geometry, queues, hidden drafts and two-host lifetime. Existing per-purpose evidence above is reused for unchanged mechanics, not relabeled as new per-control reactive migration. See the [single failure/lifetime contract](failure-lifetime-contract.md).
