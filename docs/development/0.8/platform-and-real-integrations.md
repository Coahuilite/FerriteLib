# Platform and real-source integration evidence

## Neutral means no engine in the complete dependency closure

`NeutralSources.props` is the actual shared production source inventory, not a rewritten simulation.
It now includes immutable program/XML page definitions, node identity, finite style/font/metric parsing
and background declarations, alongside the existing reactive, binding, behavior and layout sources.
The neutral half of appearance parsing uses only standard libraries. The 1.6 partial style adapter owns
the existing fit-audit fallback publication; the neutral parser still records the same redirect issue.
No rendering backend or second response graph was added.

`NeutralDependencyTests` parses real program/XML/style inputs without engine references, scans the full
recorded production inventory for platform/reflection lookup, checks its planted hidden-lookup control,
and recursively resolves every assembly reference to the current standard runtime directory. The
contract executable contains the production sources and tests; its larger BCL-only closure is an
overapproximation of the neutral source set's dependencies. It is never shipped in the mod.

## Actual 1.6 and 1.7 metadata show different adapter obligations

The 0.8 payload targets net472 and compiles with `Krafs.Rimworld.Ref`1.6.4871. Its metadata references
Assembly-CSharp1.6.9676.17735 and UnityEngine Core/IMGUI/TextRendering/InputLegacy modules, plus BCL.
Camera+3.4.7.0 and the inspected Nivarian1.6 payload use those Unity module families as well.

The actual Nivarian1.7 `.rimunity` references Assembly-CSharp1.7.9789.37269, System.Runtime10,
UnityStubs1.0, RimUnity/RimUnity.Core1.0 and Harmony3. Its `UnityEngine.Rect/Color/Event/GUI` names
resolve to **UnityStubs**, not the 1.6 Unity modules. Actual Raven1.7 additionally references Waylith
and Brutal.Vulkan. Familiar `Verse.Window/Widgets/Text` and `DoWindowContents` spelling therefore
does not establish DLL, input, text or compositing compatibility. The existing decompiler-generated
project's inferred reference paths are not authority over these measured assembly scopes.

No real UnityStubs/Waylith/RimUnity runtime reference set was present in the named Raven `refs`/`.tools`
read scope; the inspected copies contain the consumer assemblies/embedded compatibility component,
not a complete new-engine adapter SDK. Current support axes are consequently:

- **1.6:** production adapter/source compile and controlled-host evidence delivered; native awaiting human.
- **1.7:** real seam/metadata inspection delivered; neutral production contracts run engine-free;
  a compiled/running 1.7 FL adapter and native acceptance are not delivered.
- **Direct drawing:** no new backend; it follows the genuine new-engine adapter later.
