## Retained independent extensions

The following priorities are local to their broader extension track, not prerequisites that reopen the adopted R1/S1/V1 order.
They remain planning-only and retain their own adoption/exit work.

| Priority / capability | User benefit and smallest complete slice | Dependencies / migration and validation risk |
|---|---|---|
| 1 — range hit versus travel | A comfortable target without moving the value endpoints: one existing range primitive gets independent hit and travel geometry, adopted by its default wrapper and one real caller. | Original capture/eligibility owner, min/max and endpoint geometry. Preserve old overloads and pointer behavior. Native edge/scale/hit evidence is necessary; do not infer pixels from headless. |
| 2 — remaining local embedding | Reuse an owned local UI lifetime in one actual additional host. | The new named lifetime seam is the core, not a new backend. Identify the actual host callback, clipping, input qualification and teardown before adding a wrapper. Keep normal standalone users legal. |
| 3 — payload dragging | Move a typed application item with clear cancel/accept feedback, without embedding business policy in FL. | Complete target identity, capture, transfer validation, cancellation and owner exit. First slice: one typed payload, one eligible destination and all exit paths. Cross-window/IME/modal behavior is a native risk. |
| 4 — cancellable UI sequences | A bounded progression with visible progress/cues and an unambiguous terminal state. | Reuse owner cancellation/lifetime; start with non-visual sequencing, not an animation engine. One real caller must adopt start/cancel/close/failure. At-most-once business requests remain separate from visual progression. |
| 5 — broader visual scope beyond V1 | One real local transformation whose paint, hit, clip, popup and edit/IME coordinates agree. | Requires an actual backend and transform evidence. The broader sequence/transform track follows its non-visual sequence and native coordinate contract; it is not a prerequisite to the adopted finite V1 slice. No detached screenshot substitute. |
| Demand/hotspot driven — collections/shared columns/resources | Remove a demonstrated large-list or repeated-resource cost through the smallest measured consumer slice. | Use the fixed-candidate measurements for their actual inputs; require a demonstrated new hotspot. Compare visible-windowing, targeted resource revision and local caching against the current full fallback. Do not create a general background cache/resource platform first. |

The same-backend standalone bridge remains a separate Tools owner responsibility. Its isolated
current-1.7 consumption is recorded with its actual inputs; that identity is not a fixed-build
support ceiling or physical input/IME acceptance. It owns initialization, frame/input/IME,
resource/font sourcing and disposal.
Public Waylith/custom rendering is a different renderer. Reflection, copying internals and broad game
bootstrap are not substitutes authorized by this batch. Current 1.7-only work does not discharge 1.6 r6.
